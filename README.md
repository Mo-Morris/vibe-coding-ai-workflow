
# vibe coding ai workflow

## 项目介绍

在日常的工作中，很多时候会编写代码来处理一部分任务，例如处理一份表格、一份文件、或者清洗一批脏数据。如果这个任务执行是固定的流水线，你可以做成n8n或者dify这样的AI工作流。n8n或dify的AI工作流，是完全在服务端定义并运行的，虽然节点可以完全用代码执行自定义，但是比如我的某个步骤，不仅是流水线式执行的，执行完毕之后，还需要人工介入，例如数据清洗之后，还需要人工结束标注，标注之后才能进入下一个步骤，并且这个步骤的web页面用户也可以完全自己定义。这个项目在AI编写代码不是那么强大之前几乎不可能，但是现在AI写代码已经非常厉害了，所以很多时候，一个工作流的定义以及执行也将有很多的可能。对应其中的一个节点而言，本质也就是输入输出，对输入输出做加工，vibe coding来实现这些数据的处理，呈现图表，人工检查等，将会非常方便。

## 实现思路

指定工作目录，在工作目录下面创建很多二级目录，每个二级目录对应一个工作节点。
指定数据存储目录，保存每个节点的运行日志以及输入输出结果。
每个工作节点是完全自定义的，使用什么开发语言、怎么呈现数据的方式，都没有任何限制。
但是项目下面必须有一个workflow.md文件，必须包含三个字段：name、description、command，用于描述节点的名称和描述信息。
项目启动之后，有一个AI工作流的编排管理，用户将已有的工作节点编排起来。
AI工作流列表，同时记录工作流执行到哪个节点了。
数据存储格式：一个工作流执行，会在数据存储目录下，创建一个子目录。
该目录下按照工作流的节点名称，继续创建目录。
每个节点的日志，输出的结果都保留到自己的节点的目录下。
如果其他节点需要读取该节点的输出，直接读取该路径即可，不是通过命令行传递参数的方式。
